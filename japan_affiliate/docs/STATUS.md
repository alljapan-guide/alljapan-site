## 2026-11-12 duplicate photos: defect, cause, guard (owner report)
Defect: the same photo appeared in many articles; on the home page card list identical thumbnails showed (e.g. the Yamato truck on two luggage cards). Audit: 45 groups of identical photos, 122 slots, 75 extra slots in 39 articles; 11 groups on the card (slot 1) image alone; 1 article (esim) used one file twice.
Causes: (1) pipeline.fetch_images took the top Commons hit per query with no check against photos already used, so similar topics (insurance, IC card, luggage, guides) got the same file; (2) neither quality.py nor build.py compared photos across articles; (3) process shortcut: earlier sessions and this one reused "verified" photos on purpose (luggage/guide set, Kansai and Kyushu hubs) and registered copies under new keys.
Guard (pipeline/image_dupes.py): the strict build fails if any photo (same file bytes OR same Commons source page) is used in two slots, and tests/test_image_dupes.py fails CI on the same. fetch_images now skips any Commons title already in data/images.json. Existing duplicates are listed in data/known_duplicate_images.json (clean-up backlog); only slots in that list are tolerated, so no new duplicate can enter. The backlog is cleared card images first, then the rest; the list must end as [] .
Rule for every future article: never copy or reuse a photo; each slot needs its own file, or drop the slot (keep >= 2 photos).
